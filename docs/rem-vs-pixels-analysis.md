# Анализ консистентности: REM vs Pixels

Этот отчет содержит подробный анализ использования единиц измерения `px` (пикселей) и `rem` в CSS-файлах проекта Guild Master.

---

## 📊 Общая статистика

В ходе сканирования **56 CSS/SCSS файлов** в директории `src/` было обнаружено **946 объявлений** с использованием единиц `px` или `rem`.

*   **Всего упоминаний:** 946
*   **Использование PX:** 758 (80.1%)
*   **Использование REM:** 188 (19.9%)

## 🎯 Выявленные паттерны (Согласованное использование)

Анализ кода показывает, что в проекте есть определенная логика разделения единиц:

1.  **Шрифты (`font-size`)**: Преимущественно задаются в `rem` (почти 80%). Это хорошая практика для обеспечения доступности (accessibility), так как текст масштабируется в соответствии с настройками пользователя в браузере.
2.  **Границы (`border`, `border-width`)**: 100% задаются в `px`. Это обеспечивает четкость линий на экранах с любым разрешением.
3.  **Тени (`box-shadow`) и размытия (`filter`, `backdrop-filter`)**: Задаются исключительно в `px` для точного позиционирования эффектов.
4.  **Размеры экранов в медиа-запросах (`@media (max-width: ...px)`)**: 100% используют `px` (например, `480px`, `640px`, `768px`).

## ⚠️ Несоответствия и проблемы (Discrepancies)

Основная проблема заключается в смешанном и неконсистентном использовании единиц для отступов (`padding`, `margin`, `gap`) и в редких исключениях для размеров шрифтов.

### 1. Смешанные отступы и расстояния (`padding`, `margin`, `gap`)
В то время как большинство отступов в проекте заданы в `px` (более 80%), в ряде модулей они переопределены в `rem`. Это наблюдается в:
*   `ProfilePage.module.css` (например, `padding: 2rem`, `gap: 1.5rem`)
*   `LoginForm.module.css` (`padding: 2.5rem 2rem`, `margin: 0 0 1.5rem`)
*   `NotificationPanel.module.css` (`padding: 0.625rem 0.875rem`)
*   `Sidebar.module.css` (`gap: 0.75rem`)

#### 💥 Примеры критической несогласованности:
*   **Смешение единиц в одной декларации:**
    В файле `src/widgets/calendar/ui/CalendarGrid.module.css` (строка 83) свойство `padding` использует одновременно `rem` и `px`:
    ```css
    padding: 0 0.75rem 0.5rem 12px;
    ```
*   **Смешение переменных и относительных единиц:**
    В файле `src/widgets/sidebar/ui/Sidebar.module.css` (строка 12) используется формула с пиксельной переменной и `rem`:
    ```css
    padding: calc(var(--header-height) + 0.5rem) 0 1rem;
    ```
    *(При этом `--header-height` в `globals.css` равна `48px`)*.

### 2. Размеры шрифтов (`font-size`) в пикселях (29 случаев)
Несмотря на общий стандарт использовать `rem` для шрифтов, в некоторых компонентах жестко зашиты пиксели:
*   **Виджет UpcomingEventsStrip**: полностью написан с использованием `px` для шрифтов:
    *   `src/widgets/upcoming-events/ui/UpcomingEventsStrip.module.css` содержит 11 таких объявлений (например, `font-size: 10px`, `11px`, `12px`, `13px`, `15px`).
*   **Компонент UserAvatar**: использует пиксели для шрифтов инициалов пользователя:
    *   `src/shared/ui/UserAvatar/UserAvatar.module.css` содержит значения `9px`, `12px`, `14px`. Это может быть оправдано тем, что сами аватары имеют жестко фиксированные размеры в `px` (24px, 32px, 40px).
*   **Другие случаи:**
    *   `src/features/auth/ui/LoginForm.module.css` (строка 36) -> `font-size: 13px`
    *   `src/shared/ui/Button/Button.module.css` (строка 26) -> `font-size: 10px`
    *   `src/shared/ui/Select/Select.module.css` (строка 102) -> `font-size: 14px`

## 💡 Выводы и рекомендации

1.  **Согласовать размеры шрифтов**:
    Рекомендуется перевести все `font-size: *px` в `font-size: *rem`.
    *Исключение:* Шрифты внутри фиксированных графических элементов (таких как `UserAvatar`), где размер текста жестко привязан к размерам контейнера в пикселях.
2.  **Унифицировать систему отступов (padding, margin, gap)**:
    Сейчас наблюдается разделение: часть макетов версталась в `px`, часть (например, профиль, авторизация) — в `rem`.
    Необходимо выбрать единый подход. Для адаптивной верстки предпочтительнее использовать `rem` (или CSS-переменные/дизайн-токены) для всех крупных отступов (layout spacing) и `px` для мелких фиксированных зазоров.
3.  **Избегать смешения единиц**:
    Декларации вида `padding: 0 0.75rem 0.5rem 12px` усложняют поддержку и должны быть исправлены на использование одной единицы измерения (предпочтительно `rem` для текстовых блоков или `px` для табличных сеток).
